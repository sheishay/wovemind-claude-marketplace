# Where things stand on the billing app after this week's sessions

Okay, here is a summary of everything from the last few sessions, since a lot happened across different parts of the codebase and some of it is still in flight. I will try to cover it all.

First the login work, which was the main goal. We replaced the password login with magic links. The flow now is that the user enters their email on `/login`, we create a single-use token valid for 15 minutes, store a hash of it in the new `login_tokens` table, and email a link to `/login/verify?token=...`. When they click it we check the hash, check the expiry, mark the token used, and start the session. I added rate limiting of 5 link requests per email per hour, because otherwise anyone could flood someone's inbox. This is merged in PR #412 and deployed to staging; you can try it on staging now with any test account. One thing that changed along the way: originally we planned to keep passwords as a fallback, but we decided to remove password login completely, because keeping both doubled the security surface and only 3 percent of users had logged in with a password in the last 90 days. The old `password_hash` column is still in the users table, empty for new users, and will be dropped in a later migration once we are sure nothing reads it.

Then, while doing that, the integration test suite kept failing randomly on CI, roughly one run in four, which turned out to be the `test_invoice_totals` test depending on the order rows came back from the database without an `ORDER BY`. I added the `ORDER BY` and also made the test fixture use fixed dates instead of `now()`, since two other tests had a similar problem around midnight UTC. CI has been green for 31 runs in a row since then. That fix is in PR #415, merged.

We also upgraded Node from 20 to 22, because Node 20 reaches end of life in April and the Dockerfile was still pinned to it. This mostly just worked, but the `node-sass` dependency does not build on Node 22, so I swapped it for `sass` (the Dart Sass package), which is the maintained replacement and needs no code changes for our styles. The Docker image is also about 90 MB smaller now as a side effect. That is PR #418, merged and deployed to staging.

Now the parts that are not finished. The CSV export of invoices for the finance team is about half done. The endpoint `/reports/invoices.csv` exists and returns the right columns, but it builds the whole file in memory, which will fall over for the biggest customer, who has about 1.2 million invoices. It needs to stream rows instead. I estimate about half a day for that. It is on the branch `feature/csv-export` and not merged.

There is also an open bug that came up during testing: invoice due dates show as one day early for customers in time zones west of UTC, because the due date is stored as a timestamp at midnight UTC and then converted to local time in the browser. The right fix is probably to store due dates as a plain date with no time, which means a migration on the invoices table. I have not started it, and it needs a decision from you on whether we migrate existing data or only fix new invoices. This is issue #421.

Also still open: the staging email provider is in sandbox mode, so magic-link emails only reach the 10 verified addresses. Before production we need to request production access from the provider, which they say takes up to 2 business days. Nobody has requested it yet, and production launch of the login change is blocked on it.

A smaller thing: the error page for an expired magic link currently just says "Invalid token", which is unhelpful. It should say the link expired and offer to send a new one. I noted it in issue #422; maybe an hour of work.

On the side, I noticed the README setup instructions still mention `npm run build:css`, which no longer exists after the Sass change; the CSS now builds as part of `npm run build`. I fixed that in the same Node PR. And unrelated to all of this, the analytics dashboard has been slow to load for a few weeks; I did not look into it, but it might be the unindexed `events.created_at` column.

So to sum up: magic-link login, the flaky test fix and the Node 22 upgrade are all done and on staging. The CSV export needs streaming, the due-date bug needs your decision on migrating old data, the email provider needs production access requested, and the expired-link message needs rewording. The most urgent thing is requesting production access from the email provider, because it takes up to two business days and launch is blocked on it.
